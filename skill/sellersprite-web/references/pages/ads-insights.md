# 广告洞察（ads insights）

## 1. 用途

输入单个父体/子体 ASIN，反推该 Listing 在亚马逊广告上的投放架构：有哪些广告活动、广告组、投放类型，以及每个广告组在哪些周有投放活动。

- 适合：看竞品广告架构、找竞品在投的广告组/广告活动、判断某条 Listing 的广告活跃周期。
- 不适合：查具体搜索词明细（本页只展示广告组矩阵，关键词明细需在页面内展开）；查商品投放/SP 以外的广告类型（本页仅含 SP、SBV 的关键词投放，不含商品投放，也不含 SB、SD）。
- 数据来自卖家精灵网页与估算模型，不是 Amazon 官方广告后台。

## 2. URL 与导航

- URL：`https://www.sellersprite.com/v3/ads-insights`
- 查询后 URL 会带参数，例如：
  `https://www.sellersprite.com/v3/ads-insights?q=<ASIN>&marketId=1&interval=week&months=6&pageNum=1&pageSize=50`
- 导航：工作台「运营推广」→ **广告洞察**。
- 同组子导航：广告洞察 / 查流量来源 / 关联流量 / 出单词反查 / AI评论分析2.0。

## 3. 站点选择

- 查询栏有站点下拉，默认「美国站」；US 用 USD（页面价格显示 `$`）。
- 站点下拉实测包含：美国站、日本站、英国站、德国站、法国站、意大利、西班牙、加拿大、印度站、墨西哥、巴西站、澳洲站、阿联酋、沙特站。
- 本页 US 已完整验证；CA 只确认站点控件含「加拿大」，未选择、未查询，CA 数据/币种未验证。

## 4. 页面结构

1. **子导航**：广告洞察 / 查流量来源 / 关联流量 / 出单词反查 / AI评论分析2.0 / 产品监控 / 关键词监控 / 店铺上新监控。
2. **查询栏**：站点下拉、时间粒度（按周/按月）、单个 ASIN 或产品链接输入、`立即查询`。
3. **辅助入口**：`查询历史`、示例 ASIN 链接、使用帮助/视频教程。
4. **商品摘要**：ASIN、卖家、BSR、价格、评分/评分数、上架时间；下方有查竞品/关键词反查/出单词反查/查流量来源/关联流量/销量预测/加入产品库/找相似/查专利等快捷入口。
5. **汇总句**：该 Listing 在所选时间段内共计有 N 个投放小组（X 个 SP、Y 个 SBV），属于 M 个广告活动。
6. **筛选/排序**：广告类型、广告活动、广告组、所属变体、排序、时间范围；`合并并展示同一广告活动` 复选框；`导出`。
7. **时间视图**：`按周` / `按月` 切换；下方是广告组矩阵。
8. **广告组矩阵**：`section.groups-content > ul > li` 为一行；每行含广告组、广告活动、ASIN、广告类型和周期列。
9. **分页**：底部页码、每页条数、跳转。

## 5. 必填输入与可选筛选

- **ASIN**：必填，单个父体/子体 ASIN 或产品链接。placeholder：`输入单个父(子)体ASIN或产品链接，如 B00FLYWNYQ`。
- **站点**：默认美国站。
- **时间粒度**：`按周`（默认）或 `按月`；本次实测 `按周`。
- **筛选**：广告类型（全部）、广告活动（全部）、广告组（全部）、所属变体（全部）、排序（从历史到现在）、时间范围。
- **合并选项**：`合并并展示同一广告活动`，默认不勾选。
- 示例 ASIN 实测：`B08FLKHG8J`、`B07WRBDXZ8`、`B07SL2X217`；点示例会填入输入框并自动发起查询。

## 6. 操作流程

1. `bsk open "https://www.sellersprite.com/v3/ads-insights" --json`；确认标题含「广告洞察」、站点是美国站。
2. 点页面示例 ASIN（或输入单个 ASIN），页面会自动查询；也可点 `立即查询`。
3. 等汇总句从 0 变为实际数量，再读结果矩阵。汇总句和数据是异步加载的，刚点完可能先看到 0 或空态。
4. 先读汇总句（投放小组数、SP/SBV 数、广告活动数），再读矩阵首行和分页 total。
5. 需要看某周详情时再点周单元格；本版验证没有展开，只读矩阵。
6. 不要点 `导出`；本次不提交导出任务。
7. 结束 `bsk close`。

## 7. 结果表/矩阵关键列

本页**不是** Element UI 的 `.el-table`，没有常规表头。结果区是自定义矩阵：

- 容器：`section.groups-content`
- 行：`section.groups-content > ul > li`
- 每行左侧标签：`广告组<编号>`、`广告活动<编号>`、`ASIN`、广告类型（如 `SP` / `SBV`）
- 右侧周期列：`MM/DD-MM/DD` 形式的周列；实测从 `05/10-05/16` 到 `11/01-11/07`，共 28 列。

实测首行（2026-11-14，US，ASIN `B08FLKHG8J`）：

- 广告组：`广告组YWTX`
- 广告活动：`广告活动HZ2E`
- ASIN：`B08FLKHG8J`
- 广告类型：`SP`
- 周列单元格是活动矩阵块；本次只读标签和周期列，没有展开单元格里的明细/悬浮值。

汇总句实测：`290 个投放小组（289 个SP、1 个SBV），属于 224 个广告活动`。

## 8. 排序、分页、每页条数

- 分页：实测 `total=290`、`pageSize=50`、`currentPage=1`，当前页读到 **50** 行。
- 矩阵每页 50 行；翻页后重新读 `section.groups-content > ul > li`，不要沿用上一页。
- 排序/筛选：页面有排序下拉和广告类型/广告活动/广告组/所属变体筛选；改动后结果会重查，必须重新读汇总句和 total。
- 时间粒度：`按周` / `按月` 会改变列数和 URL 的 `interval` 参数；切换后重新读。

## 9. 导出

- 页面上有 `导出` 按钮；本次验证**没有点击**。
- 导出是异步/有副作用的操作，需要时按 `workflow.md` 的导出规则单独向用户确认，只提交一次。

## 10. 空态与页面坑

- **空态**：本次先看到 `主人-暂无相关数据哦!`，随后数据加载完成变为 290 组；不要把加载中的空态当最终结果。
- **不是 el-table**：`read-table.js` 只能读到分页 `total=290`、`pageSize=50`，`headers` 和 `items` 为空，`source=none`；不要因为 `rowCount=0` 就判空。
- **自定义矩阵读取**：用 `bsk observe` 找到 `section.groups-content > ul > li`，再用只读 `bsk evaluate` 统计行数和读取行文本；不要把整页 HTML dump 进报告。
- **汇总句异步**：刚查询时可能显示 0 个投放小组，等汇总句变成实际数字再读。
- **示例 ASIN 自动查询**：点示例 ASIN 会直接查询，不要再点一次 `立即查询` 造成重复查询。
- **广告类型范围**：页面提示仅包含 SP、SBV 的关键词投放，不含商品投放，也不含 SB、SD；报告不要写成“全部广告类型”。
- **周列没有年份**：页面周列只显示 `MM/DD-MM/DD`；报告写周范围时注明页面未显示年份。
- **站点**：切站点后要重新查询并核对币种/数据；CA 未验证。

## 12. 典型配方

1. **看竞品广告架构**：输入竞品 ASIN → 读汇总句（投放小组/广告活动数）→ 逐行看广告组和广告活动编号 → 需要时点周列看活跃周期。
2. **判断广告活跃度**：按周视图看某广告组在哪些周有矩阵块；按月视图看长期趋势。
3. **按广告活动筛选**：在「广告活动」下拉选一个活动，读该活动下的广告组；筛选后重新读 total。
4. **合并同一广告活动**：勾选 `合并并展示同一广告活动`，看活动级汇总；勾选后重新读行数和汇总句。
5. **后续分析**：把 ASIN 拿到「关联流量」看关联来源，或「出单词反查」找出单词；本页不写广告、不导出。
