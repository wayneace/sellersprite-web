# 关键词挖掘（keyword miner）

## 1. 用途

从一个种子词出发，拓展出亚马逊上与它相关的关键词，并给出每个词的需求与竞争指标（月搜索量、购买量、购买率、展示/点击、SPR、标题密度、商品数、需供比、广告竞品数、集中度、PPC 竞价等）。

- 适合：种子词拓词；选 Listing/PPC 关键词；找低竞争高需求的相关词；判断一个细分市场的词根结构。
- 不适合：按市场维度筛词（用「关键词选品」）；反查某个 ASIN 的流量词（用「关键词反查」）。

## 2. URL 与导航

- URL：`https://www.sellersprite.com/v3/keyword-miner`
- 导航：工作台「产品」→ 关键词优化 → **关键词挖掘**；页面子导航第一项。
- 查询后 URL 形如
  `https://www.sellersprite.com/v3/keyword-miner/?q=yoga%20mat&marketId=1&batch=0`
- 过滤面板的条件**不写入 URL**；报告筛选条件时要读页面回显，不能只看 URL。

## 3. 站点选择

- 查询栏最左侧是国家下拉（显示「美国站」+ 国旗），不是一排按钮。
- US 用 USD，CA 用 CAD；PPC 竞价等货币字段随站点。
- 切换站点后重新查询；核对币种和总数。详见 [sites.md](../sites.md)。
- CA 只确认了站点控件可切，未逐页验证 CA 数据/币种。

## 4. 页面结构

1. **子导航**：关键词挖掘 / 关键词反查 / 流量词对比 / 拓展流量词 / 关键词转化率 / 实时查竞价 / 关键词收录 / 关键词词库。
2. **查询栏**：国家下拉、日期（默认「最近30天」）、种子词输入框、重用上次筛选、立即查询、查询历史、示例词。
3. **查询后**：出现结果工具栏（对比/加入词库/导出明细/导出/搜索结果数/自定义列）和「搜索结果过滤」面板。
4. **过滤面板**：相关度 ~、ABA月排名、月搜索量、月购买量、购买率、展示量、点击量、SPR、标题密度、商品数、需供比、广告竞品数、点击总占比、转化总占比、PPC竞价、单词个数、词根匹配、Amazon Choice、排除/包含关键词、匹配方式、开始筛选、重置条件。
5. **结果表**与**分页**（`read-table.js` 可读）。

## 5. 必填输入与可选筛选

- 种子词必填（「输入关键词，如: flashlight」）；可以带空格，如 `yoga mat`。
- 匹配方式：精确匹配（默认）/ 广泛匹配；另有「仅包含词根的关键词」「仅AC推荐词」开关。
- 包含关键词 / 排除关键词：逗号分隔。
- 类目：过滤面板的「所属类目」下拉。
- 过滤面板可设的区间：相关度（0.5–100）、ABA月排名、月搜索量、月购买量、购买率、展示量、点击量、SPR、标题密度、商品数、需供比、广告竞品数、Top3 点击总占比、Top3 转化总占比、PPC 竞价、单词个数。
- **过滤面板改完必须再点一次「开始筛选」**（第二次页面查询）；不点只是改了表单，结果不会变。
- 日期默认「最近30天」；页面提示数据月初更新上个月，报告写页面月份控件的值。

## 6. 操作流程

1. 打开页面，确认国家是目标站点。
2. 填种子词（可先不改匹配方式），点「立即查询」；等待结果表和「搜索结果数」出现。
3. 需要收窄时，在「搜索结果过滤」面板填条件，再点「开始筛选」；确认 total 变化。
4. 动作后重新 `observe`/读状态；点击返回成功不等于查询生效。
5. 读取用 `<skill-dir>/scripts/read-table.js`（本页命中 `el-table-store`）。
6. 翻页/排序后重新读表；记录页码、每页条数。

## 7. 结果表关键列

实测表头（2026-11-12，US，种子词 `yoga mat`）：

`#`、`关键词`（含中文翻译）、`展示10条相关产品`、`所属类目`、`月搜索趋势`、`相关度`、`月搜索量 / 增长率`、`月购买量`、`展示量 / 点击量`、`SPR`、`标题密度`、`需供比 / 商品数`、`广告竞品数`、`ABA 集中度`、`PPC竞价 精准`、`市场分析`、`操作`。

常见字段口径（详见 [fields.md](../fields.md)）：

- 月搜索量、月购买量、购买率是该关键词的自然月口径；购买率 = 购买量 / 搜索量。
- 展示量、点击量是该词结果页所有 ASIN 的总量，不是单个 ASIN。
- 需供比 = 搜索量 / 商品数；SPR 是 8 天维持首页所需销量估算。
- 单词个数（词长）是**过滤面板字段**，不一定是结果列；筛选时按页面标签「单词个数」填写。
- `平均价格/平均评分数/平均评分` 若出现在相关产品里，是**点击第一的 ASIN** 的值，不是结果均值（旧验证）。

## 8. 排序、分页、每页条数

- 默认按**月搜索量**降序（旧 CLI 默认排序字段 21 = searches；live 首行是种子词本身）。
- 每页固定 **50** 条；分页组件是 Element UI，`read-table.js` 能读 `total/pageSize/currentPage`。
- 过滤面板的条件不改变 URL；分页/排序可能改变页面状态但不一定改 URL，报告以页面回显为准。
- 页面显示「搜索结果数」，与分页 total 可能有差异；两个都记录。

## 9. 导出

- 结果工具栏有「导出明细」「导出」；导出是异步任务。
- 先确认筛选条件和总数；只提交一次；到「我的导出」看状态；文件出现后用 `bsk download`。
- 本页验证**没有提交导出任务**。

## 10. 空态与页面坑

- 无结果时表格空态显示「主人-暂无相关数据哦!」，同时「搜索结果数: 0」、分页 total=0。
- 优先用最新 `observe` 的 ref 或可见标签；只有种子词输入框/「立即查询」在 `observe` 里没有 ref 时，才用可见 placeholder 定位：
  - 输入：`input[placeholder^='输入关键词']`
  - 查询：`.el-input:has(input[placeholder^='输入关键词']) .el-input-group__append button.my-btn`
  - 不要用全局 `button.my-btn`（页面有 5 个）。
- 「开始筛选」是过滤面板的第二次查询；只填条件不点按钮，total 不会变。
- 过滤条件不写入 URL，复制 URL 不能复现筛选；报告必须写页面回显的条件。
- 页面底部有「高频词/词组个数」区域，属于辅助信息，不是结果表。

## 12. 典型配方

1. **种子词拓词**：输入 `yoga mat` → 精确匹配 → 立即查询 → 按默认月搜索量读前 50 个词。
2. **低竞争高需求词**：过滤面板设 月搜索量 ≥1000、需供比 ≥1、标题密度 ≤10 → 开始筛选 → 读 total 和表。
3. **从词跳到下一步**：选中词后去「关键词反查」看哪些 ASIN 在吃这个词，或去「选产品」按销量/价格找商品。
4. **判断词根结构**：看页面底部高频词/词组个数，再决定用广泛匹配还是仅词根。
